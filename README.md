# ObsidianWeb

**Obsidian の Vault を唯一のデータソースにする、DB を持たないローカルファースト・ナレッジワークベンチ。**

Markdown ノート群（frontmatter・wikilink・見出し）をそのままドメインモデルとして扱い、
案件ボード・カレンダー・面接準備・タイムライン・3D ナレッジグラフ・学習ループをリアルタイムに構築する。
Next.js (vinext) / React 19 / TypeScript、デプロイ先は Cloudflare Workers。

## この設計の何が面白いか

### 1. データベースを持たない、という設計判断

`db/schema.ts` は**意図的に空**。永続化層は Obsidian の Vault（ただの Markdown ディレクトリ）そのもの。

```
Obsidian (Local REST API) ──► app/api/vault?scope=… ──► readAllNotes() ──► 各ビュー
        ▲                          │
        └── 書き戻し：状態は frontmatter のスカラー行差し替え／復盤・練習は追記専用ノート ──┘
```

- コピーを作らない＝**二重口径が構造的に発生しない**。Obsidian で編集しても Web で編集しても事実は一つ。
- API キーはサーバープロセスだけが持ち、ブラウザにもリポジトリにも出ない（`lib/server/obsidian.ts`）。
- 書き戻しの原語は 2 つだけ。**状態**（案件の状態・経路・跟進、TODO の状態）は
  `lib/server/frontmatter-patch.ts` が各ルートの許可した key のスカラー行だけを差し替え、本文には触らない。
  **記録**（復盤の注釈・フィードバック・練習）は `lib/server/note-append.ts` が追記専用ノートへ本文追記する。
  「読む→書く」が原子的でないため、ルート内でノートパス単位に直列化する
  （`createKeyedSerialQueue`。別ノート・別ルートは互いに待たせない）。
- 楽観ロック：`status_updated` を持つ案件はそれを、TODO はディスクの `mtime` を版として送り、
  ずれていれば 409 を返して画面側が再読込する。案件状態の書き込み後は派生統計を
  `derivedState: stale` と明示し、`vault:stats` を再実行するまで「同時点の集計」を装わない。
- 経路（channel）は**歴史事実**として扱い、状態変更で上書きできない。未採点は 0 点ではなく「—」。

### 2. 「生成ブロック」による派生値の単一事実源

集計値・比率・推移といった**派生データを人が手で書くことを機械的に禁止**する。

```markdown
<!-- generated:<id> 勿手改 -->
（スクリプトだけが書き換える領域）
<!-- /generated -->
```

派生値が一度散文に溶けると上流と切れ、上流が変わっても追随せず、間違っていても誰も気付かない。
実際にこの事故が起きたので、**事実（人が書く）／派生（機械が計算する）** を型として分離し、
`npm run vault:check`（frontmatter 検証）と `npm run vault:stats`（再生成）で強制している。

同じ思想を評価データにも適用した。会社の適合評価（六軸）は frontmatter の構造化 YAML だけから描き、
資料が無い軸は `null` のまま**空欄**にして、合計点を合成しない（`lib/company-overview.ts`）。
schema と criteria のバージョンを分けて持ち、旧口径のレーダーを新口径と並べて比較させない。

### 3. 検査を CI ではなく三層に置く

Vault は「別マシンには存在しないかもしれない外部データ」なので、コードのテストに縛ると
CI が理由なく落ちる。赤信号が増えると誰も見なくなる——そこで検査を三層に分けた。

| 層 | 発火 | 挙動 |
|---|---|---|
| エージェントの Stop hook | AI が応答を終える度 | 不整合なら **exit 2 で差し戻し**、理由を AI に返す |
| `npm run dev` 起動時 | 画面を見る時 | warning のみ、ブロックしない |
| Vault リポジトリの pre-commit | `git commit` 時 | 不整合なら**コミット拒否** |

`vault:check` は frontmatter の列挙値だけでなく、準備稿の版（`prep_version`）ごとの章構成、
`case`／`meeting` の二択、会社画像・適合報告の入れ子 YAML まで検証する。

### 4. 増分キャッシュ：workerd に `fs` が無い前提で組む

Vault 全体を毎回読むのは遅い。しかしサーバーは workerd 上で動くため
（`nodejs_compat` は仮想ファイルシステム）、`fs` の mtime は使えない。

そこで **REST API の `POST /search/` に JsonLogic `{"var":"stat.mtime"}` を投げ、
1 リクエストで全ノートの mtime を取る**（実測 12ms）。以降は
「1 回のスキャン + mtime が変わったファイルだけ再取得」になる（`lib/server/vault-cache.ts`）。
ビュー側は `/api/vault?scope=` で必要な type のノートだけを受け取る（`lib/vault-scope.ts`）。

書き込み直後の読み取り整合性と metadata cache の遅延は実測に基づいてテストで固定し、
看板の連打で起きる後勝ち消失はルート単位の直列キューで防ぐ。

### 5. 準備稿の版を Vault 上で共存させる

面接準備稿は同一案件のなかで旧 12 節（v1）と新 5 章（v2）が混在する。履歴稿の本文は書き換えず、
Web が**選択した稿ごと**にレイアウトを切り替える。研究資料の累積は「その稿の時点まで」で止め、
後続回の URL を過去回へ倒灌させない（`lib/interview-prep-index.ts`）。
案件（job-case）の無い面談は `meeting: [[面談TODO]]` で系列を作れる。

追記専用のノートも同じ発想で読む。回答練習のキューは `attempt / complete / snooze` のイベント列を
追記するだけで、`queued / active / completed / snoozed` は**畳み込みで導出**する（`lib/review-practice.ts`）。
話者裁定は最新の明示的な裁定だけを採り、「覚えていない」のような不確定な申告は未解決へ戻す。

### 6. 3D 舞台：相互作用の力学を零依存の純関数に切り出す

three.js で意味的関係を四本の旋臂を持つ「記憶星図」として、活動量を「時之航道」として描く。
UnrealBloom＋高光ソフトニー、三層の星空、ポインタの「エネルギー探針」と粒子の動量場。

- 探針の位置・傾きは臨界減衰、エネルギーは指数アタック／リリース——いずれも**解析解**
  （`lib/stage-interaction.mjs`）、
  粒子の滑走は動量場の**解析解**（`lib/stage-motion.mjs`）。フレームレートに依存せず、
  GLSL と CPU 側の式は**テストで逐字照合**する
- マウスとハンドトラッキングは同じ状態機を共有する。押下／ドラッグ中は入力源をロックする
- ハンドトラッキング（MediaPipe Tasks Vision、wasm とモデルは**自ホスト**）：捏合の閾値は
  手ごとの**自適応包絡**（画面アスペクト補正済み）＞ 存档校准 ＞ 既定値の順で決め、
  短捏の最短時長は 24ms。捏住／握拳ドラッグは OrbitControls の回転と同じ数式を使い、
  双手で平移・縮放・回転。握拳による即時接管と位移で判定する抓取は識別側が持つ
- 既定は 2D の「関係地図」（一跳近傍）と「時間列表」（月索引・日密度）。3D は「探索モード」として記憶される

### 7. ローカル LLM ブリッジ

生成系は `127.0.0.1` にのみバインドしたローカルブリッジ経由（`scripts/codex-bridge.mjs`、
起動側は `scripts/dev-with-obsidian.sh`）。

- 起動スクリプトが起動ごとに使い捨てトークンを発行し、Web とブリッジを同一トークンで束縛
- ログイン方式を検証し、API キー方式なら**実行を拒否**
- 子プロセスに `OPENAI_API_KEY` / `CODEX_API_KEY` を継承させない
- 起動スクリプトがポート衝突時に空きポートを自動選択（「古いブリッジが居るのに新しい画面が 503」を排除）

| ビュー | 内容 |
|---|---|
| 総覧 | 「当前行動」カード（TODO の状態をその場で 進行中／完了／保留 に書き戻す）＋ 行動・進行中案件・未応募求人・7 日以内の予定・返信待ち・復盤・本日の重練 |

| 岗位机会（案件ボード） | 「決策台」（待判断キュー＋詳細）が既定。全文検索・多軸フィルタ・最大 3 件比較。状態変更時に経路を一緒に保存し、跟進（等待対象／跟進日／次の日程）を書き戻す |
| 選考与分析 | 進行中・面接段階・結果待ち・応募可の 4 枚の glance と手札分析 |
| 本場面接 | 案件／面談ごとの準備稿。v2 は 会社総覧／面談縦覧／志望動機／逆質問／資料 の 5 タブ＋臨場備用。六軸適合レーダー（資料不足の軸は空欄）、最大 3 社の横並び比較。v1 稿には面接前に通読する「導読」モード |
| 通用準備 | 回答ライブラリ（全文閲読レイヤーで連読可）。共通資産は本場面接の資料リンクから浮層で開く |
| 面接レビュー | 一場全体の「総合導読」→ 逐語稿と注釈の突き合わせ → 5 次元スコア。小説式の全文閲読（中文／日本語切替・話者裁定反映） |
| 回答重練 | 復盤で積んだ改善回答を、先に声に出してから開示。順調／詰まり／不明の自評と 完了／翌日再練 を追記だけで記録 |
| 日本語トレーニング | 面接の証拠から組む集中訓練。主動詞塊・誤り修正・面接官表現・回答構成・職務技術・事実口径の 6 種を、快速走査→集中修正→圧力テストの 3 段階で回す。能力画像・問題地図・訓練語料タブ |
| 専項訓練 | 中訳日の語塊・固定搭配・句型置換・即興表現・安全な言い換えの 5 種の練法 |
| 資料庫 | 信頼層バッジ＋要約カード、分区・場面の交差フィルタ、scope／sort を URL に保持 |
| 全文閲読モード | ノート詳細から書籍風の全画面リーダーへ。字号 5 段階・目次・文書情報・反リンク・読書位置の復元。記憶星図／時之航道ではシーンを離れず舞台内の暗色レイヤーで読む |
| 関係地図 / 記憶星図 | 既定は会社／スキル／ノートを中心にした一跳近傍の 2D 地図。3D は四旋臂の銀河配置、マウス／ハンド共通のエネルギー探針 |
| 時間列表 / 時之航道 | 既定は月索引・日密度・種別絞り込みの年代記。3D は今日に着地し、日単位パネルで当日のノートと日程を一覧 |

## 動かし方

Obsidian と **Local REST API** プラグインが起動している状態で：

```bash
npm install
npm run dev
```

`http://localhost:3000`。起動スクリプトが Obsidian のプラグイン設定から API キーを読み、
サーバープロセスにだけ渡す。

| 環境変数 | 用途 |
|---|---|
| `OBSIDIAN_VAULT_PATH` | Vault の場所 |
| `OBSIDIAN_CONFIG_PATH` / `OBSIDIAN_API_URL` | 既定値の上書き |
| `CODEX_BRIDGE_PORT` | ブリッジのポート（既定 `43127`） |

## 品質ゲート

```bash
npm test    # tsc --noEmit → build → node --test（440 tests）
npm run lint   # eslint --max-warnings 0
```

`npm test` は型チェックとビルドを含む。テストは純関数として切り出したデータ層
（`lib/*.ts` / `lib/*.mjs`）を中心に、パーサ・正規化・競合条件・レンダリング結果・
GLSL と CPU 式の一致・手勢のフレーム列まで覆う。

会社名の表記ゆれ（全角/半角・「株式会社」の位置・括弧書き）のような、
実運用で実際に壊れた形はすべてテストに固定してある。
