# 老师交流信箱

留言是运行时 R2 私有资料，独立于 Vault、D1 和发布快照。源码、测试夹具、日志、自动 AI 输入不得包含真实留言或引用。测试全部使用内存存储与虚构内容。

## 访问与站点门禁

浏览器先通过站点访问密码，再使用留言共享码建立老师会话。本人本机服务端代理使用已有 `FEEDBACK_OWNER_SECRET`：只有 `feedback-owner-auth.ts` 列举的精确路径和方法可跳过外层站点 Cookie，留言 handler 仍验证运行时配置、本人凭据、来源和输入。该凭据不能访问资料 API、静态快照或维护入口。代理不把管理密钥或远端 Cookie 交给浏览器。

站点密码登录使用已有 `FEEDBACK_BUCKET`，在 `site-access/limits/` 下按固定 60 秒窗口对客户端预占额度，每窗口最多 10 次（成功也计入）。客户端地址以既有站点会话密钥做 HMAC，不保存原始 IP。条件写入保证跨 Worker 实例及并发请求共享额度；超限返回 429 和窗口剩余秒数。未绑定 R2、读取失败或条件写入持续冲突时，新登录返回 503；有效浏览会话不依赖该存储。每实例每分钟最多检查 100 个旧限流对象并清理过期项。

## 接口

- `GET /api/feedback/summaries`：默认 25 条，`limit` 为 1–50；返回 `items / nextCursor / revision / total / facets`。按 `updatedAt DESC, id DESC` 排序。筛选参数为 `filter=all|unread|open|working|done|hidden`、`company`、`page`、`author`、`sessionId`、`blockId`、`q`。
- `cursor` 绑定参与者、筛选条件摘要、分页大小、信箱和已读版本。版本变化返回 409，调用方重取第一页并保留当前详情；条件或身份不符返回 400。隐藏内容不会出现在老师列表、筛选项或全文搜索中。
- 摘要仅含位置、状态、作者、计数、最后作者、首条正文前 100 字符、引用前 65 字符。`quoteLength / quoteRevision` 用于在已有原文上核对引用位置，不携带完整引用。`q` 明确非空时才按需读取可见话题的完整正文、完整引用及作者名，保持原有全文匹配语义。
- `GET /api/feedback/unread`：返回 `revision / readRevision / unreadThreads`，支持 `ETag / If-None-Match` 和 304；仍先独立鉴权。只计可见话题中的他人未读消息。
- `GET /api/feedback/threads/:id`：按需返回完整引用与消息。原有 `GET /api/feedback/threads` 保留兼容，但新版界面不再用它轮询。
- 创建、回复继续使用客户端稳定消息 ID；状态修改可携带稳定 `operationId`。已读仍提交实际显示的消息 ID，不能仅提交时间戳或最大 ID。

初始化会话后，页面可见时每 30 秒只请求未读接口，聚焦事件合并重复请求。资料版本变化再刷新列表和打开的详情，列表检索等待输入稳定 300 毫秒。暂时失败保留已显示资料并提供重试，不能显示为空信箱。

## R2 正本、迁移与恢复

`feedback/v1/threads|messages|reads` 继续保留原格式及正文。线程元数据新增单调 `revision`、已提交消息 ID 索引和已执行状态操作 ID。不可变消息正文先保存，再以条件写入把消息加入已提交集合；详情和摘要只呈现已提交消息。不同并发回复不会互相覆盖，旧状态操作重放不会覆盖更新后的状态。

派生层为 `feedback/v2/summary-index.json` 和 `feedback/v2/read-summary/{participantId}.json`。摘要索引的内部消息引用仅含消息 ID 和作者 ID。较慢的请求只能提交更高的线程版本，不能覆盖较新摘要。已读摘要合并实际消息 ID；新回复即使与已读写入同时发生，也不会被提前标记。

每次业务写入先保存 `feedback/v2/pending/` 恢复日志，再写 v1 正本、提交元数据及 v2 投影，全部成功后才删除日志。存储中断返回 503 和 `Retry-After: 3`；下次读写自动幂等恢复。恢复每次最多处理 20 条日志，仍有积压时继续返回可重试错误。日志同样是私有运行时资料，不能导出到仓库或 AI 输入。

旧信箱第一次使用时建立摘要索引；各参与者第一次使用时从旧已读 ID 构建已读摘要。初始化以条件写入发布，失败不发布半成品，多实例迁移不会覆盖胜出的新索引。完成后，无变化的未读轮询为 **2 次 GET + 1 次 LIST**；加留言鉴权配置读取共 **4 次 R2 操作**。不读取线程正文或单线程已读文件；传输字节数仍随摘要及消息 ID 索引规模增长。全文搜索、迁移、待恢复日志及实际写入不计入该稳态预算。

回滚前先停止新写入并让 `pending/` 清空；保留全部 v1 正本。旧版代码可以读取 v1 数据。若回滚期间发生旧版写入，恢复新版前仅删除 `feedback/v2/summary-index.json` 和 `feedback/v2/read-summary/` 派生对象，使新版重新合并 v1 消息及已读记录。不要删除 v1 数据、待恢复日志或运行时秘密。迁移与回滚操作应由部署人员在授权存储环境执行，测试不接触真实信箱。
