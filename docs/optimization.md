## 代码变更与验收契约

| 范围 | 变更 | 必须满足的验收条件 |
| --- | --- | --- |
| 发布版本访问 | 以发布根清单的当前版和保留版作为唯一白名单；正文、查询、分页绑定同一版本。 | 已撤回版本返回 409，即使 D1 仍留有对应行；清单或获准索引不可用返回 503，不退回任意旧版或空列表。 |
| 读取层与日历 | 固定预热来源，按缺失批次续传；热读取复用完整版本，HTML 日历统计读取 D1 汇总，详情按需加载。 | 不为计数拉取整套正文或日历明细；同版不重复导入；跨版本时摘要、详情和游标一致；同步失败保留获准的完整资料。 |
| 留言代理鉴权 | 有效本人服务端 Bearer 只放行精确留言路径及方法；外层豁免后继续留言独立鉴权。 | 错误凭据、老师 Cookie、未知路径、资料 API 和维护 API 均不能借此绕过站点门禁；浏览器收不到服务端管理密钥或远端 Cookie。 |
| 站点密码限流 | 复用 R2，以现有会话密钥 HMAC 标识客户端，CAS 预占固定分钟窗口中的十次额度。 | 跨 Worker 和并发共享额度；第十一次返回 429 与 Retry-After；R2 缺失或失败时新登录返回 503，已有效的浏览会话仍可用。 |
| 留言摘要与未读 | 分页摘要、按需详情、显式全文搜索；可见时轻量未读轮询，支持 ETag / 304。 | 首条正文和引用预览分别限制为 100 / 65 字符，不返回消息数组；旧游标遇版本变化返回 409；全文后半内容仍可命中；隐藏内容不进入老师列表、筛选、搜索或详情。 |
| 留言写入恢复 | v1 正文保留，持久 pending 日志、消息提交索引、单调修订与派生摘要条件写入。 | 消息、元数据、摘要、已读或日志清理中断均可恢复；重复提交不重复消息；旧状态重放不覆盖新状态；只标记实际显示的消息 ID，迟到回复保持未读。 |
| 派生数据维护 | 独立维护密钥与站点会话双重保护，预检清单摘要，每轮处理一个版本、每表最多 1000 行及最多 1000 个孤块。 | 获准版、当前版、后续导入和共享正文不删除；策略变化 409；事务失败整轮回滚；相同请求可以推进多轮清理；空版本集合也能回收孤块。 |
| 静态封存 | 发布目录只包含 `OWSEALED1` 加密封装，支持保留旧秘密的封存密钥轮换。 | 平台绕过 Worker 直接返回的当前、历史静态文件仍不能读出 JSON；缺密钥或解封失败不退回明文。 |

## 安全回退与维护密钥撤销

本轮预留的安全回退点是发布 **v36**，对应代码提交 **`f76d6603`**（`Close withdrawn revision access and harden private service authentication`）。该点包含撤回版本访问保护和私有服务鉴权加固。回退只能使用这份安全基线或之后的合格版本；更早版本不得恢复已撤回资料的访问能力。

回退时使用与目标部署相匹配的密封静态资源及运行时解封密钥，保留 D1 / R2 正本。若使用 `SITE_ASSET_SECRET_NEXT` 轮换，新旧密钥按部署对应关系保留，不把新密封资源配给旧密钥。R2 先停止写入并恢复完 pending 操作；旧代码写入后的再次升级按 [feedback.md](feedback.md) 仅重建 v2 派生层。回退不通过删除 Vault、清空 R2 或回滚事实数据完成。

维护操作完成后立即关闭临时维护能力：

1. 串行调用维护接口直至 `complete:true`，再重新预检，核对获准资料仍可正常查询。清单变化时先重新预检，不沿用旧删除集合。
2. 在站点的运行时秘密配置中删除 `SITE_MAINTENANCE_SECRET`，保存并使配置变更生效；检查名称已消失即可，不回显任何秘密值。
3. 使用有效站点会话回读 `POST /api/read-model/maintenance/prune`：即使携带刚才的旧维护 Bearer，也应返回 503“维护入口未启用”。匿名请求仍由外层站点门禁拒绝。
4. 验证普通页面、按需正文和留言仍可用；清除维护进程中的临时凭据、Cookie 文件及环境变量。常规访问、留言与封存秘密继续按各自用途保留。

## 本机性能与结构证据

本节依据本轮本地的 `obsidianweb-structural-evidence.json` 和 `obsidianweb-implementation-performance.json`，结构测试仅使用合成资料。证据文件保留在执行环境的临时目录，不作为公开资料或长期仓库资产。下表记录优化前后相同接口口径的观测值；时间单位为毫秒，响应大小单位为字节。

| 接口 | 首轮耗时：前 → 后 | 热请求 p50：前 → 后 | 热请求 p95：前 → 后 | 响应大小：前 → 后 |
| --- | ---: | ---: | ---: | ---: |
| 日历 calendar | 72 → 161 | 30 → 40 | 32 → 51 | 42688 → 43602 |
| 资料库 library | 98 → 33 | 19 → 29 | 22 → 33 | 31498 → 31498 |
| 搜索 search | 299 → 60 | 27 → 26 | 28 → 27 | 12998 → 12998 |
| 短词搜索 short-search | 56 → 50 | 23 → 29 | 26 → 45 | 13151 → 13151 |
| 面试 interview | 36 → 168 | 24 → 26 | 27 → 37 | 39789 → 39789 |
| 复盘 review | 24 → 32 | 23 → 27 | 33 → 29 | 34002 → 34002 |
| 洞察 insights | 23 → 29 | 24 → 28 | 26 → 37 | 61433 → 61433 |

**这些数据不能证明整体延迟提升。** 搜索首轮和部分指标下降，多个接口的热请求或首轮指标反而升高。这里的“首轮”仅是该轮测量的第一个请求，并非重新启动隔离容器后的真正冷启动；开发服务的编译、缓存和并发活动会引入噪声，不能将差值全部归因于代码变更，也不能外推为线上收益。日历响应新增 `revision / day` 字段，响应大小增加 914 字节，属于返回契约变化；其余六项响应大小一致。

结构证据确认了以下工作量边界：

- **搜索与目录：** 400 篇合成笔记中，命令面板空查询和常见词查询均只返回 8 行目录，3 次 D1 batch，不计算资料库筛选统计或全量相关度计划；近期资料库返回 24 行，3 次 batch，不重建正文。相关度查询首次仍需完整候选排序，观测为 22 次 batch、18 次正文重建查询；后续分页复用排名计划，降至 3 次 batch、1 次正文重建查询。不能将首次相关度检索描述为常量成本。
- **缓存：** 结果与排名计划共享最多 64 项、估算 8 MiB、5 分钟 TTL 的预算；缓存保存结果 DTO、选中片段、排名路径与命中数、筛选和候选信息，没有长期正文文本缓存。该预算不是整个进程的内存上限。
- **留言：** 100 个话题、每话题 5 条消息并完成迁移后，未读响应为 51 字节，含鉴权共 3 次 R2 GET + 1 次 LIST、0 次 PUT、0 次消息正文 GET；相同 ETag 返回 304，响应正文为 0 字节，存储读取预算不变。25 条摘要响应为 26800 字节；该首次参与者读取另创建一次已读摘要，稳态不再写入。单话题详情才读取其 5 条消息，观测为 9 次 GET + 2 次 LIST。浏览器每 30 秒可见时轮询，支持条件请求和进行中请求去重。

CSS 按“客户端外壳、留言入口和服务端入口静态依赖闭包中的唯一 CSS 路径并集”计数，gzip 使用级别 6。同一口径的原始大小从 **807921 降至 735960 字节**，gzip 从 **132369 降至 120606 字节**，分别减少 71961 和 11763 字节，约 8.9%。当前值均低于构建测试的 768000 / 126000 字节门槛；入口仍含外壳样式，阅读工作区和图谱指针样式标记已不在这份闭包中。这项证据证明入口 CSS 负载缩减，不等于全部路由资产或页面耗时同比下降。
