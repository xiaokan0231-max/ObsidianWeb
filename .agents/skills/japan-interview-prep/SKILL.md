# 日本面接准备

把日本面接准备做成一条可复用流水线：**读已有资产 → 调研 → 分析 → 只写增量 → 落 vault → 在 Web 验证**。

面向的典型场景：非母语（尤其中国人）候选人在日本求职，日语读得懂但口语偏弱，需要「能直接说出口的日语话术 + 母语理解的策略」。

## 🔴 这个 skill 不从零生成话术

候选人已经把大量资产沉淀在 Obsidian vault 里了：26+ 张标准回答卡、逐社转职理由台本、高危问题台本、
当日短语集、单词文法帳、NG集，以及**每场面接后的五维回答品質復盤**。

**每次从零生成，等于把这些教训全部丢掉重犯一次。** 实际发生过的事故：AI 生成话术时创作了
「数百ノード規模の分散クラスタ」这种无出典的夸张，被本人纠正后写死成规则；
「日次約10億件」也曾因归属冲突一度停用，后来才依据权威素材复核恢复。这些变化只存在于 vault 里 —— 不读就会重犯。

所以：**固定内容读 vault 并嵌入，不重写；每次只生成本次面接特有的部分。**

## 開始前：从 vault 读（別のどこかから作り始めない）

| 组 | 读什么（vault 路径） | 用途 |
|---|---|---|
| **① 权威** | `10_关于我/求職硬性約束.md`（条件・语言・职种的最上位判断基准）<br>`10_关于我/技術スタック.md`（年数・技术归属的**唯一权威**）<br>`10_关于我/STAR素材集.md`（数字的出典与注意） | 任何数字・年数・条件都以这三份为准。**其他地方的值都是快照** |
| **② 话术资产** | `20_求職/_素材/面接標準回答集.md`（p01〜 卡片，含「使用边界」「证据」）<br>`_素材/転職理由台本.md`・`_素材/高危質問_個人化台本.md`<br>`_素材/自己紹介_音読台本.md`・`_素材/当日フレーズ集.md`<br>`_素材/単語文法帳.md`・`_素材/NG集_禁句と口癖.md` | 共通题**直接嵌入引用**，不重写。写新话术前先确认库里有没有 |
| **③ 教训层** | **先读 `20_求職/_素材/面接傾向_横断.md`**（机器聚合：五维推移・最弱维・反复的戦略タグ・优先复习块↔卡片对应）<br>再读本案件相关的 `*_回答品質復盤.md`（单场细节）<br>`10_关于我/日本語矯正_精選.md`（口癖） | **本次要重点练什么**由过去的失分决定，不是凭感觉。横断先看趋势，单场看细节。同社二轮必读上轮 |
| **④ 本案件** | 对应的 `type: job-case` 笔记（採点・status・channel）＋求人原文<br>同社既往的 `*_復盤.md`・`_<会社>.md`（company 卷宗） | 勝ち筋・逆質問・二轮对策 |

- **读了 ③ 之后，想定問答的选题就不该只按「轮次高频题」**。把「上次栽在哪」作为加权项（见阶段 3）。
- Claude 记忆只作**兜底**（语言偏好等 vault 里没有的），不再是主信道。**vault 与记忆冲突时 vault 优先**。
- **在留资格现况・年収口径・他社选考状况**这三项每次都要向本人确认——它们变化最快，vault 里是快照。
  若本轮来不及确认，§1 必须明确写成 `⚠️ 本人确认未了`，**禁止把旧值伪装成现况**，也不能把准备文档报告为“信息已补全”。
- 若信息仍不全（例如没有求人原文、不知道面接官是谁），**先问本人**，别硬编。

## 五阶段流程

### 阶段 1：调研公司 + 面接官
按 [references/research-sources.md](references/research-sources.md) 做。要点：
- 官网多是 SPA，用浏览器工具（用户已登录 Chrome）看渲染后的 `/about-us`、`/recruit`、服务/产品页；`WebFetch` 抓 Green 访谈、招聘平台等 SSR 页。
- 多信源交叉（官网＋口碑站＋Green访谈＋搜索）。小公司口碑样本少，别过度解读。
- **拿到面接官姓名就查其公开背景**（LinkedIn/登壇/技术博客）——这是价值最高的一步，能改写打法。提醒用户 LinkedIn 留痕。
- ⚠️ **边查边把用过的 URL 存下来**，阶段 3 的リンク集要用（事后想不起来）。
- 外部事实必须能回到**可点击的直接页面**。具体公告、案例、IR 事实不能只给官网首页；保存 URL 时同时记一句“该页支持什么事实”。
- 产出：会社速查、役员/面接官画像、技术拆解、对该候选人的追い風。

### 阶段 2：定位主轴 + gap 分析
- 一句话给候选人定位（诚实、对口该公司的真实需求，不是简历罗列）。
- 逐条识别 gap（技术栈不符/无某实绩/日语），每个都用「正向重构」翻译成价值（见 [references/methodology.md](references/methodology.md)）。
  gap 不藏，但要框成「熟练度/时间问题，不是能力/价值问题」。
- gap 的三段式回法在 `_素材/高危質問_個人化台本.md` 里已有成型的型，**先看那个**。
- gap 不等于全部主动披露。先按用途分类：
  - **角色成立／合法入职的边界**（JD 必须的顾客折衝、签证等）→ 到相关话题时主动给出；
  - **JD 未要求的弱项**（例如求人没有英语要求）→ 被问到再答，不主动追加负面信息。

### 阶段 3：只生成增量

> 🔴 **先复制模板：** [assets/面談準備_テンプレート.md](assets/面談準備_テンプレート.md)。
> 这份模板**只持有每次要写的部分**，固定资产一律用 `![[…]]` 嵌入 vault 正本。
> **不要把嵌入替换成正文内容。** 复制一份进去就等于把口径变成二重管理，必然漂移。

#### 📎 嵌入即可（不写）

| 模板节 | 嵌入 |
|---|---|
| §5 自己紹介本体 | `![[自己紹介_音読台本]]` ＋只写「今回の締めの一文」 |
| §8 転職理由 | 🔴 `![[転職理由台本#⭐ 音読用スクリプト（注音つき・面接直前に声出し）]]`——**必须指定节** |
| §9 当日フレーズ集 | `![[当日フレーズ集]]` |
| §10 単語文法帳本体 | `![[単語文法帳]]` ＋只写「今回の会社固有用語」 |
| §12 NG集本体 | `![[NG集_禁句と口癖]]` ＋只写「今回固有の one-liner」和当日チェックリスト |
| §6 共通題 | 选卡片填表；**只把 3〜5 张高危卡**用 `![[面接標準回答集#pXX …]]` 整段带进当日文档 |

🔴 **`転職理由台本` 绝不整篇嵌入。** 那份笔记含【内部】层＝面接で絶対に言わない内容（逐社的内部说明、
义悠事业停止的背景）。整篇嵌入会把这些印到本人面接前在手机上读的文档里。
build 脚本装了守卫，混入即 exit 1——**报错不是脚本坏了，是嵌入范围写错了**。

#### 🔁 每次真正要写的

按 [references/workflow-templates.md](references/workflow-templates.md) 的模式多角度起草+评审合成：

- **§1 速査／§2 勝ち筋／§3 案件・技術／§4 面接官攻略**：调研结果落地。面接官的公开背景在 §4 变成战术。
- **§1 最上方必须有「面談直前の一枚」**：定位、最大确认点、志望动机、逆質問3题和 closing 各一行；
  紧接一张「时效性3项」表，逐项写确认日期或 `⚠️ 本人确认未了`。桌面端打开后先看这一屏，不让用户在长文里找临场结论。
- **志望動機**（模式A）：找到真正打动候选人的点（常不是「产品好」，而是更深的共鸣，如公司的方法论/工程精神），
  围绕它写，落到候选人自身可信的实践。⚠️ 库里 p11 是**框架**，本社版每次都要重写。
- **§6 会社特化想定問答**：共通题从库里选（不重写），只写该公司特有题。
  🔴 **选题要看过去的失分**：`面接傾向_横断.md` 的反复タグ和「优先复习块↔卡片对应」直接决定本次带哪些卡，
  在表的「前回の失点」列写清上次怎么栽的（出典写到 `qNN`）。同社二轮要逐条对上轮復盤写「上次没答好的这次这样答」。
  ⚠️ 横断表里标着「**対応カード無し**」的优先复习块＝库里的空洞。这次面接会问到的话，
  就在阶段 5 把它补成新卡片（p26 SES可否就是这么来的）。
- **§7 逆質問**：按面接官分（HR走人/文化/长期；技术者走实务深度；决策者走愿景）。第1问从技术/实务入较自然。
- **§10 会社固有用語**：从调研材料提取频出词，每词＝表记＋注音＋中文义。顺手收 1-2 条公司豆知識（社名词源/产品命名梗），雑談加分用。
- **§11 会社研究リンク集**（必含）：阶段 1 存的链接按用途分类（①求人・採用 ②公式・プロダクト ③CEO・思想
  ④資金調達・企業データ ⑤ニュース・提携 ⑥口コミ），每链一句注释，并标注「面談前最終復習只需这3个★」。
  口碑站没查到有效样本时，如实写「样本不足勿过度解读」。
  - 所有 URL 用 `[说明文字](https://…)`，不得只写域名或“官网见”；
  - ★ **恰好3条**，优先为：求人正本／最能支撑志望动机的官方直接页面／最能判断业务实态的官方页面；
  - Web「本场面试」会自动把这节抽到顶部，因此不要把 Teams 会议 URL 混进 §11。

#### Web 信息架构契约：12个内容节，6个主模块

vault 继续保留 12 个 `##`：它们是嵌入、出典、交叉引用和离线 HTML 的稳定地址，**不要为了页面变简洁而把正文硬拼成6个超长章节**。
桌面端 Web 必须按任务把它们渐进分组：

| Web 主模块 | 内部内容节 | 用户此时要解决的问题 |
|---|---|---|
| **1 临战速查** | §1 | 进面谈前一分钟，我只要记住什么 |
| **2 公司与岗位** | §2／§3／§4／§11 | 公司怎么赚钱、岗位是什么、对方是谁、证据在哪 |
| **3 自我叙事** | §5／§8 | 我是谁、为什么转职 |
| **4 想定问答** | §6 | 对方会怎么问、我怎么短答 |
| **5 反向提问** | §7 | 我要用哪三问判断岗位 |
| **6 当日工具** | §9／§10／§12 | 听不懂怎么办、词怎么读、最后检查什么 |

- 顶层始终只出现这6个主模块；内部节只在进入对应模块后显示为子项。
- 左右方向键和底部分页切换**主模块**，不是在12节之间逐个跳。
- 搜索仍覆盖全部12节，命中结果可以直接打开相应子项。
- 不新增第13个同级 `##`。新内容必须归入现有节；确实改变信息架构时，先同步 Web 分组和本表。

#### 回答长度契约（公司特化新话术）

- 每题先写 `##### 20秒版（既定）`：**2〜3句、一个结论、一个证据、一个落点**，说完必须能自然停住。
- 只有确有必要时才写 `##### 追問されたら追加する`。追问层不重复20秒版，只补证据或边界。
- 禁止默认答案连续出现3段长台词；“30秒以内”不是标签，必须实际按非母语语速朗读检查。
- 可否题第一句先给 `はい／難しい／経験はありません`，再解释。20秒版结束后主动把话权还给对方。

#### 🔴 写完任何新话术，先过这道检查（lint）

生成的内容里不许出现下面任何一项——这些都是已经付过学费的：

1. `_素材/NG集_禁句と口癖.md`「絶対に言わないこと」表里的 ✗ 侧表达
2. `_素材/単語文法帳.md` G表**没有**的数字（「数百ノード規模」＝禁用）。
   `日次約10億件` 已于 **2026-07-25** 依据权威素材复核恢复；可用时必须说清是**上海創藍／SMS 基盤（2019-20）**，
   使用“約”，不得说成精确值，也不得归到工品匯
3. 与 `技術スタック.md` 不一致的年数・技术归属（Java 是**约12年**并须附内訳）
4. 相关卡片「使用边界」明确禁止的说法（例如英语不说「ビジネスレベル」、不说「日本語で顧客折衝可能」）
5. **自己贬低・低锚点**：不主动说转职多、不先报低于 JD 中位的年収、不自曝「雇ってもらえるか分からない」
   （→ NG集「自己貶下・低アンカー」节，出典是实际复盘里 riskControl 全维最低的那场）
6. **无关的主动负面披露**：每个“先说”都必须标出它对应的 JD 必须条件、角色成立或合法入职判断；否则改为“被问到再答”
7. **临场长度**：公司特化回答若没有20秒版，或20秒版超过3句，视为未完成

判定标准：**相手の判断材料になる境界＝出す。自分への評価・値付け＝出さない。**

### 阶段 4：落 vault + 在 Web 验证

1. **产物落 vault**：`20_求職/<会社名>/面接準備_<YYYY-MM-DD>.md`，frontmatter：
   `type: interview-prep` / `company` / `date` / `round` / `format` / `interviewers` / `case`（回链 job-case）。
   frontmatter 必须在**第1行**，否则读不到。
2. **交付前扫一遍**：`{{ }}` 占位符是否全部替换掉、章节交叉引用（§3、§7…）对不对得上、嵌入的节名是否与 vault 完全一致。
3. **回流 company 卷宗**：把不会随本轮变化的公司事实（商业模式、业务方向、官方链接）写回同目录 `_<会社>.md`；
   面接官战术、当轮问答、日期和 Teams 链接只留在 `面接準備_<日付>.md`。卷宗不得继续保留“会社研究未着手”。
4. **桌面端 Web 验证（默认交付）**：打开「本场面试」，确认：
   - 主导航恰好6个模块；公司与岗位、自我叙事、当日工具只在进入后显示子项；
   - 顶部出现3条重点外部资料，展开后能看到 §11 的全部 URL；
   - 「案件正本」能打开对应 job-case；
   - §1 第一屏能看到临场一枚和时效性3项；
   - 逆質問保留 1/2/3 顺序；vault 双链能跳到指定节。
5. **`npm run vault:check`**：会校验完整 frontmatter、case 是否指向 job-case，以及 `![[…]]` 的目标笔记和节名。
   断链＝Web 上整节静默变空，目视很难发现，所以必须让脚本报。
6. **离线 HTML 仅在本人明确需要离线／手机阅读时导出**：

```bash
python3 scripts/build_interview_html.py \
  --input "$OBSIDIAN_VAULT_PATH/20_求職/<会社>/面接準備_<日付>.md" \
  --output 面接準備.html \
  --title "○○社 最終面接準備｜肖侃" \
  --subtitle "決裁者×本部長の2対1／対面・約1時間" \
  --chips "性質＝技術面|年収OK済→証明が主眼"
```

脚本自动：`![[…]]` 从 vault 展开、`漢字（かな）`→ruby 头顶注音、【あなた】/【面接官】对话框、▷中文策略框、
>tip框、**tab 式章节切换**、深色模式、标签平衡自检、ruby 注音健全性警告、**内部层守卫**。
Web 是默认正面交付；HTML 是确有离线访问需求时的备份，不再为了“也许会用手机”自动生成。

**离线 HTML 的 tab 式章节切换**：离线版仍以每个 `##` 作为 tab，**一次只显示一节**；
桌面 Web 则使用上面的6主模块＋子项分组，两者用途不同。
nav 高亮当前 chip（自动横滚到可见）＋底部 `n / N` 进度＋`前へ/次へ` 翻页按钮。渐进增强——无 JS 时退化为纵向长页，
打印时自动展开全部节。内置在脚本里，Markdown 侧不用做任何标记。

**Markdown 格式约定**（生成内容时遵循）：
- `## 大节` → section + 导航 chip　　`### 小节` → 蓝标题　　`#### / #####` → 紫标题（想定問答的 Q 用这个）
- `【あなた】…` → 绿框(你的话)　　`【面接官】…` → 紫框(对方想定发言)
- `▷ 中文策略…` → 黄框　　`▶ 补充…` → 蓝框　　`> tip…` → 金框　　`- 项` → 列表　　`**加粗**`
- `[表示名](https://…)` → 可点击链接（新标签打开）——リンク集一节用这个
- **`![[ノート]]` / `![[ノート#節]]` → 从 vault 取正文，必须单独成行**；行内写的会原样露出（脚本会警告）
- **`[[ノート]]`（无 `!`）→ 出典表示**，渲染成纯文本。正文里提到别的笔记时用这个，不要用 `![[…]]`
- 文中所有日语难读词写成 `漢字（かな）`，脚本转 ruby。**注音括号必须全角 `（）`、括号内纯假名**
  （混入空格/`〜`/中点/半角括号会导致 ruby 失配、括号原样露出——build 会打印警告）；
  `〜八年（ななはちねん）` 这种跨波浪号的要拆成 `約8年（やくはちねん）`

### 阶段 5：收尾与回流

- 关键部分（面談直前の一枚／志望動機／语言策略／外部链接入口）在桌面浏览器截图确认；若生成 HTML，再校验标签平衡。
- 提醒候选人：最该练的（通常是自我介绍音读3遍 + フレーズ集扫一遍 + G表数字）、当天注意点、时效性事项（如日程回复）。
- **回流（这才是资产越用越准的原因）**：
  - 面接中发现库里缺的高频题 → **在 `面接標準回答集.md` 新增卡片**（按固定 section 规格：
    `分类/优先级/问题/目的/标签` ＋ `### 标准回答` `### 30秒版` `### 回答结构` `### 使用边界` `### 证据`）。
    **证据必须回链具体整理稿/復盤/素材**，不写无出典的漂亮话。
  - 口径有更新（年収・在留・转职说法）→ 改 vault 正本，**不改各社的准备笔记**（它们只是引用）。
  - 面接后走 `review-interview-answers` 做回答品質復盤 → 跑 `npm run vault:stats` 重算 `面接傾向_横断.md`
    → 下次本 skill 的阶段 0 ③ 自动读到新的趋势。**这就是资产越用越准的回路。**

## 关键提醒

- **一次 ≠ 最终**：一次多是 HR 看人柄，最终是决策层看技术+条件。按轮次调重心（方法论第七节）。
- **口径一致**：年収/在留/跳槽等敏感项跨文档不能矛盾。**正本只有一份，其余都引用它。**
- **诚实是底线**：绝不帮候选人编造实绩——面接官会验真，坦诚+重构永远优于吹嘘。
  数字必须能回到 `STAR素材集.md` 的出典；查不到出典就不用那个数字。
- **迭代友好**：面完一轮拿到反馈/下一轮信息，复用同一套流程更新文档，不重来。
