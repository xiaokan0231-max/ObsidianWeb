# 五维评分准则

## 面談体裁（2026-07-28 本人裁定で追加）

カジュアル面談・エージェント面談など「相手が説明する側」の場では、正式面接と同じ物差しを機械的に当てない：

- **说明フロー中のブロック**（相手がスライド・会社説明を続けている区間）：一言の認領・共感が正しいリズム。長い自己アピールを「すべきだった」と減点しない。数字・実績の展開は「対話場面」（相手が話を止めてこちらの返答を待った瞬間）に限って期待する。
- **機会成本 vs 失误**：対話場面で証拠を出せなかったのは `opportunity`（少赚了）、直接質問への漏答・答非所問は `major`（做错了）。この区別は severity の enum が機械的に保証する——説明フローの遠慮を `major` で記録してはいけない。
- **目的達成と診断の分離**：面談の目的（例：次ラウンドの招待獲得）を達成したかは全体評価の冒頭に明記し、五維点数はあくまで次戦に向けた診断として書く。目的達成をもって診断項目を消さない（体裁と無関係な項目——聞き返し定型・語彙誤用・直接質問への漏答——は正式面接で必ず再来する）。

（実例：2026-07-16 モルゲンロットも同じカジュアル面談で87点——体裁は点数の上限ではなく、直接質問の数と、聞かれた質問への応答品質が点差を作る。）

## 通用原则

**不要自己打分。** 每一维只输出扣分明细（`deductions`），维度分＝`100 − Σpoints`，总分＝五维等权平均，都由服务器算。
这条是硬约束：扣分必须能指到具体 qNN、具体 sNN、具体一句「为什么这会影响面试官的判断」。
**说不出扣在哪，就不能扣分。**

> 为什么改成这样：旧口径下 2026-07-28 Sharing_Innovations 的问题理解拿了 86 分，
> 但那一维的理由从头到尾全是好话（「正しく捉え」「回復行動として評価する」），
> 14 分是凭「感觉不到 90 分」扣掉的，本人根本无从知道要改什么。
> 分数由扣分推导之后，这种幽灵扣分在结构上就不可能存在了。

### 扣分档

`severity` 决定 `points` 的可用区间，越界会被服务器夹回：

| severity | points | 用在什么情况 |
|---|---|---|
| `major` | 10–25 | 核心子问漏答、答非所问、明确的招聘风险表达 |
| `moderate` | 5–9 | 答到了但明显不完整，或要对方追问才对齐 |
| `minor` | 2–4 | 点状瑕疵，不改变面试官的判断 |
| `opportunity` | 1–3 | 没做错，只是白白少赚一次加分 |

- **满分是起点，不是奖赏。** 找不到可举证的扣分点就返回空数组＝100 分。
  不要为了让分数「看起来合理」而编造扣分，也不要用一句泛泛的话吃掉十几分。
- 同一件事影响两个维度时可以分别记，但要各自写清**该维度**受损的原因，不要复制粘贴同一段话。
- 一次轻微停顿是 `minor`，不要放大成整场缺陷；反过来，反复出现的同一个毛病要合并成一条并按 `major`/`moderate` 记。
- 语言不自然只有在它改变含义、直接性或风险时才在本层扣分；纯语法问题留给一层批注。

### 每条扣分要写什么

- `labelZh`：一句话说清扣在哪，能被单独读懂。「複合質問の AI・MCP に未回答」，不是「回答不够完整」。
- `detailZh`：现场实际发生了什么 → 为什么这会影响面试官的判断。
- `fixZh`：下次具体怎么做就不会再扣。要可执行、可练，不写「注意完整性」这种没法照做的话。
- `evidenceSentenceIds`：该 qNN 块内的 sNN。

## 问题理解

判断是否正确识别面试官意图、复合子问、追问变化和确认性问题。

什么算扣分：

- `major`：回答的是另一个问题、误判问题前提、对重要追问完全没有反应。
- `moderate`：把复合问题听成单问（只接住其中一支）；要面试官换个说法或追问两轮才对齐。
- `minor`：一次没听清，但当场确认后答对了——只扣「没有一次对齐」的成本。
- `opportunity`：听懂了，但没有把对方真正想验证的点复述出来确认，错过了一次「这个人抓得住重点」的印象分。

不扣分的情况（写进 `rationaleZh`，不要写成扣分）：

- **主动聞き返し是回复行为，不是缺陷。** 不猜、先确认再回答，本身正确；只有当它反复发生、或确认后仍答错时才扣。
- **「不知道答案」不等于没听懂。** 只有语义证据、追问反应或本人聴解批注支持时，才在本维扣分；单纯不会答属于证据可信度或覆盖。

## 覆盖完整度

比较 `askedPoints` 与 `answeredPoints`，关注是否覆盖面试官真正需要判断的内容。

什么算扣分：

- `major`：岗位关键问题的核心子问始终没答（对方拿不到「可否／能不能」的结论）；大段回答停在相关话题上，没有回答问题。
- `moderate`：主要问题答到了，但遗漏第二子问、结果、本人角色或改善措施；被要求排序却给并列。
- `minor`：流程性、细节性的半答，不影响判断。
- `opportunity`：对方没明说但显然想知道的边界／条件，没有主动补上。

复合问题漏答在本维度按 `major` 或 `moderate` 记，看漏掉的那一支对录用判断有多重要。
寒暄和纯流程块既不扣分也不加分——不要因为它们「答得好」就少扣别处。

## 直接性

判断是否先给结论、答案是否容易被面试官提取、展开长度是否服务于问题。

什么算扣分：

- `major`：全程给不出可提取的结论；反复自我修正把关键事实说糊了。
- `moderate`：最终答到了，但背景铺垫过长、顺序混乱，或要对方追问才确认结论。
- `minor`：一处措辞绕了一圈，随后自己收了回来。
- `opportunity`：结论对了，但放在段末——先说出来会更有力。

详细不等于不直接。只在细节掩盖结论或超出问题需求时扣分。

## 证据可信度

判断主张是否由具体经历、本人角色、行动、技术细节、数字和结果支撑，且前后一致。

什么算扣分：

- `major`：把学习兴趣说成实务能力；关键数字前后矛盾且没有当场澄清；大量泛称撑起核心主张。
- `moderate`：有相关经历但结果模糊、没量化；没区分本人职责与团队成果；重要判断只凭观点和自我评价。
- `minor`：本应确知的事实用了「多分」这类不确定措辞；口径小偏差且当场被澄清。
- `opportunity`：对方给了展开的机会，手上有可核对的实绩却没拿出来。

不要因为技术名词多而自动少扣。事实边界清楚的「没有实务经验」比夸大的熟练度更可信，**不扣分**。

## 风险控制

判断回答是否在不隐瞒事实的前提下，避免制造与问题无关的招聘风险。

什么算扣分：

- `major`：贬低前公司、客户、领导或同事（尤其人格判断）；未被问就主动抛出裁员、频繁转职、薪资落差等负面材料；用绝对化措辞否定自己的能力。
- `moderate`：暴露岗位关键空档后没有说明边界和补齐计划；对国家、企业文化、技术作绝对化概括；回答重点与岗位／职级期待错位。
- `minor`：一处措辞偏重，但上下文能兜住。
- `opportunity`：对方指出短板时没有给出既有反证——不算说错，但白白让担忧留在记录里。

不扣分的情况：**被直接问到的负面事实如实回答**（倒産、离职理由、他社选考）。
隐瞒才是风险，如实说不是。只在「没被问却自己递上去」时才按 `negative-oversharing` 扣。

不要把日本文化刻板印象当作评分规则。只根据对方的提问、反应、岗位语境和可合理预见的招聘判断评价风险。

## 总分解释

总分只概括五维，不替代分项。报告应明确「哪一维拉高、哪一维拉低」。

**不要为了接近旧分而调整扣分。** 从旧口径（凭感觉给分）切到扣分推导后，分数普遍会变高——
因为过去那些说不出理由的扣分现在扣不动了。这是修正，不是通胀：
如果新分明显高于旧分，说明旧分里本来就有幽灵扣分，在 `summaryZh` 里说明变化来自评分契约即可，
不要靠编造扣分项把分数压回去。
